# ADB 多区域随机点击器

一个面向 Windows 的 Android 自动点击工具。通过桌面界面采集手机屏幕、框选多个矩形区域，并按顺序执行随机坐标、随机次数和随机间隔的点击任务，适用于已获授权的设备测试和重复操作。

界面使用 Python Tkinter，点击通过 ADB 执行，实时投屏与鼠标控制使用 [scrcpy](https://github.com/Genymobile/scrcpy)。便携包内置运行环境、ADB 和 scrcpy，使用者无需安装 Python 或配置 ADB 环境变量。

> 使用前请阅读文末的[使用须知与免责说明](#使用须知与免责说明)。项目自身的开源许可证目前尚未确定，详见[许可证与第三方组件](#许可证与第三方组件)。

## 功能

- **截图框选**：在手机截图上拖动选择矩形，可连续添加多个点击区域，也可手动输入坐标。
- **多区域执行**：按列表顺序点击，支持区域编辑、删除和排序。
- **独立随机设置**：各区域分别设置每轮点击次数与完成后的等待范围；每次点击独立随机选择区域内坐标。
- **毫秒步长随机等待**：时间以秒输入，支持三位小数；轮间隔、区域内点击间隔和区域间等待分别配置。
- **多屏选择**：支持按屏幕尺寸和点亮状态选择折叠屏内屏、外屏等设备屏幕。
- **配置管理**：扫描指定目录的 JSON 配置，支持快捷加载、另存、更新、删除和导入导出。
- **交互式投屏**：默认关闭，开启后通过视频流预览；窗口可移动、缩放，支持鼠标点击、滑动与长按。
- **便携运行**：提供 Windows EXE 打包脚本，生成包含依赖的 ZIP。

## 环境要求

| 场景 | 要求 |
| --- | --- |

不同厂商对多屏信息、截图与输入注入的支持可能不同，请先在目标设备上验证。当前附带的二进制面向 Windows，不提供 macOS、Linux 或 Windows ARM 原生发行包。

## 快速开始

### 使用便携包

获取项目提供的 `AdbClicker-portable.zip`；如果尚无预构建包，可按下文的构建步骤自行生成。

1. 将 ZIP **完整解压**到可写目录，不要在压缩包内直接运行。
2. 双击 `AdbClicker.exe`，无需 Python 命令。
3. 连接手机，在手机上允许 USB 调试，点亮并解锁要操作的屏幕。
4. 保留默认“内置 ADB”，点击“刷新设备”，选择目标设备。

便携包结构：

```text
AdbClicker.exe
adb/                 # ADB 及其 DLL、声明文件
scrcpy/              # 视频投屏客户端、服务端及依赖
configs/             # 用户配置存放目录
README.md
```

分发时请提供完整 ZIP，不要只复制 EXE。程序也支持手动指定 ADB 路径，点击“使用内置 ADB”可恢复默认。

### 创建并执行点击任务

1. 点击“刷新屏幕”。折叠屏或多屏设备按尺寸和点亮状态选择目标屏幕；默认选项为“自动选择主屏”。
2. 点击“采集屏幕并框选”，在截图上按住鼠标左键拖出矩形，支持向任意方向拖动。
3. 填写区域名称、每轮最少/最多点击次数，以及完成后等待的最小/最大秒数，点击“添加此区域”。已添加区域显示为绿色框，可连续添加多个区域。
4. 点击“完成框选”返回。选中区域后可编辑并点击“更新选中”，或通过“上移”“下移”调整顺序。
5. 设置全局轮间隔、区域内点击间隔与循环轮数。建议首次使用先设为 `1` 轮，检查点击效果；`0` 表示无限循环。
6. 点击“开始”执行，点击“停止”结束任务。运行日志与错误显示在主界面。

截图缩放只影响显示，框选结果会换算为手机屏幕实际像素坐标；原点位于左上角，矩形边界包含端点。“仅填入主界面坐标”用于修改已有区域，返回后还需点击“更新选中”。

截图是采集时的静态画面。手机页面变化后应重新采集；开始任务前程序会读取截图并校验区域边界，但不会识别按钮、文字或页面是否符合预期。

## 随机与计时规则

| 设置 | 作用 | 默认值 |
| --- | --- | --- |
| 轮间隔 | 每轮开始前等待，第一轮也会等待 | 20～22 秒 |
| 区域每轮点击次数 | 每个区域每轮独立随机抽取一个整数次数 | 可逐区域设置 |
| 区域内点击间隔 | 同一区域相邻两次点击之间等待 | 0.2～0.5 秒 |
| 区域完成后等待 | 当前区域所有点击结束后，等待再执行下一个区域 | 1～2 秒，可逐区域修改 |
| 循环轮数 | 完成指定轮数后停止，`0` 为无限循环 | 0 |

每次点击独立随机抽取矩形内的整数坐标。随机次数和等待范围均包含上下限，上下限相同表示固定值。

时间以**秒**为单位输入，最多三位小数，每次按 **1 毫秒步长**随机取值。例如等待 `N～N+M` 秒，若 `N=2`、`M=1.5`，填写最小值 `2.000`、最大值 `3.500`，即从 2000～3500 毫秒中随机取值。区域完成后等待允许 `0～0`，表示不额外等待。

例如三个区域依次为 A、B、C：

```text
等待轮间隔（20～22 秒）
  → 点击 A（次数随机，各次之间使用区域内点击间隔）
  → 等待 A 的完成后等待（例如 1.200～1.800 秒）
  → 点击 B
  → 等待 B 的完成后等待（例如 3.000～4.500 秒）
  → 点击 C
  → 若还有下一轮，重新等待轮间隔；否则直接完成
```

- 区域之间仅使用上一个区域的“完成后等待”，不叠加区域内点击间隔。
- 最后一个区域的“完成后等待”不参与本轮执行；进入下一轮使用全局轮间隔。
- 移动区域顺序时，其等待设置随区域移动。
- 等待从上一条 ADB 点击命令返回后开始；每轮开始时间差包含上一轮执行耗时。
- 毫秒指**随机取值步长**，并非触发精度保证。操作系统调度、设备响应和 ADB 通信都会带来额外耗时。

## 配置管理

默认读取程序目录下的 `configs/`：源码版为项目根目录，EXE 版为 EXE 所在目录，不受启动工作目录影响。

| 操作 | 说明 |
| --- | --- |
| 刷新 | 重新扫描当前目录的 JSON 文件，不递归扫描子目录 |
| 选择目录 | 切换配置目录，仅对本次运行有效 |
| 加载选中 / 双击列表项 | 加载该配置到界面 |
| 另存为新配置 | 使用填写的名称新建文件，同名文件不会被覆盖 |
| 更新当前配置 | 保存到当前已加载的文件；单击其他列表项不会改变更新目标 |
| 删除选中 | 经确认后删除选中的文件；界面中的参数仍保留，可重新另存 |
| 从文件加载 / 导出配置 | 通过文件对话框导入或导出 JSON |

修改区域字段后，先点击“更新选中”，再保存配置。外部导入的配置可另存到列表目录。

配置保存设备标识、ADB 设置、所选物理屏幕、区域及计时参数。当前保存格式为版本 2，兼容版本 1；加载旧配置时，会把原全局区域间隔填入各区域等待设置。设备或屏幕变化后，应重新确认设备、屏幕及坐标。

文件采用 UTF-8 编码，保存使用临时文件加原子替换。发布 ZIP 只加入配置目录说明，不包含本机个人配置；重新打包也不覆盖已有 `dist/configs/*.json`。仓库忽略 `configs/*.json`，放在其他位置的个人配置需自行检查，避免提交设备标识或业务信息。

## 实时屏幕预览与操作

主界面的“实时屏幕预览”默认关闭，每次启动需手动开启，不随配置保存。开启后使用内置 scrcpy 在独立窗口显示当前所选屏幕的**视频流**；截图框选仍使用单次截图。

| 操作 | 效果 |
| --- | --- |
| 拖动窗口标题栏 | 移动预览窗口 |
| 拖动窗口边缘或四角 | 自由调整窗口宽高，画面保持原比例，空余位置留黑边 |
| 双击标题栏 / F11 | 最大化或还原 / 切换全屏 |
| 左键点击画面 | 在手机对应位置点击 |
| 按住左键拖动 / 按住不动 | 滑动 / 长按 |
| 关闭窗口或取消预览开关 | 停止投屏 |

窗口缩放后，scrcpy 会换算画面中的触摸坐标。预览窗口中的操作会实际作用于手机；手动操作前建议停止随机点击任务，避免两种输入交错。

默认预览参数为最长边 1280 像素、最高 30 FPS、视频码率 4 Mbps，实际帧率取决于设备和画面变化。电脑端使用软件解码；音频、键盘输入和剪贴板自动同步关闭。

切换设备或屏幕会重启视频流，退出主程序会结束其启动的投屏进程。scrcpy 按上游流程将临时服务端传到手机运行，无需安装 APK。预览占用设备视频编码和电脑解码资源，可独立关闭。

## 已知限制与常见问题

- **设备列表为空或显示 offline / unauthorized**：确认 USB 线支持数据传输、驱动可用、手机已允许本电脑调试；重新连接后刷新设备。
- **折叠屏截图全黑或提示屏幕未点亮**：点亮并解锁目标内屏/外屏，刷新屏幕后选择对应屏幕。部分应用可能限制截屏或投屏，本工具不绕过这些限制。
- **折叠或旋转后点击位置不对**：先停止任务，刷新屏幕并重新截图框选。运行期间应保持方向、分辨率、折叠状态及目标页面稳定。
- **预览能看但无法操作**：检查手机是否允许调试输入；部分厂商需要额外的 USB 调试安全设置。仅在自己拥有或获授权的设备上启用相应权限。
- **提示找不到 ADB、scrcpy 或 DLL**：重新完整解压 ZIP，确保 EXE 旁有 `adb/` 和 `scrcpy/`，不要只移动 EXE。
- **停止后仍有一次点击或稍后才停止**：等待可立即中断，但已发出的 ADB 命令需返回或超时（单条命令超时为 15 秒），已发送的点击无法撤回。
- **ADB 操作失败**：任务会终止并显示错误，不自动重试点击；排查日志后再启动。
- **构建无法覆盖 EXE**：关闭正在运行的对应 EXE，再重新构建。

多屏识别依赖设备 `dumpsys display` 提供的物理与逻辑屏幕映射。截图使用物理屏幕 ID，点击使用当前对应的逻辑屏幕 ID。工具不会自动唤醒、解锁手机，也不识别界面元素或跟踪页面跳转。运行中配置锁定，停止后再修改。

## 开发与构建

### 从源码运行

在项目根目录的 PowerShell 执行：

```powershell
python .\adb_clicker.py
```

也可运行 `start.ps1`。若 PowerShell 策略不允许执行脚本，可使用上面的 Python 命令运行源码版。

### 构建便携包

确认 `vendor/adb/` 和 `vendor/scrcpy/` 文件完整，在项目根目录执行：

```powershell
.\build.ps1
```

构建脚本会创建项目内的 `.build-venv`，安装 `requirements-build.txt` 指定的 PyInstaller，然后生成：

```text
dist/AdbClicker.exe             # 无控制台窗口的程序
dist/adb/                      # 内置 ADB
dist/scrcpy/                   # 投屏依赖
dist/configs/README.txt         # 配置目录说明
dist/README.md
dist/AdbClicker-portable.zip    # 完整分发包
```

PyInstaller 仅用于构建，EXE 使用者无需安装。ADB 与 scrcpy 放在 EXE 旁的独立目录，避免后台进程占用单文件程序的临时解压目录。修改源码后需要重新构建；`build/`、`dist/` 与构建环境不纳入 Git。

### 验证

项目测试使用 Python 标准库 `unittest`，不需要安装 pytest：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q adb_clicker.py click_engine.py config_store.py screen_preview.py tests
git diff --check
```

部分测试创建 Tkinter 窗口，需要可用的桌面会话。自动测试模拟设备交互，不向真实手机发送点击；真机上的屏幕选择、截图、坐标与交互效果仍需在目标设备验证。

### 目录结构

```text
adb_clicker.py          # Tkinter 主界面、截图框选与任务管理
click_engine.py         # ADB 通信、屏幕解析与随机点击执行
config_store.py         # 配置文件管理
screen_preview.py       # scrcpy 启动参数与进程生命周期
tests/                 # 自动测试
configs/               # 本机配置目录
vendor/adb/             # ADB 二进制与上游声明
vendor/scrcpy/          # scrcpy 二进制、依赖与来源信息
requirements-build.txt # 构建依赖
build.ps1              # EXE 与便携 ZIP 构建
start.ps1              # 源码启动脚本
```
